# Programming and Technology Profile

Apply this profile only to technical courses. The teacher's stack, audience, and desired outcome determine depth and tooling. Use [tech mapping](tech-mapping.md) and the preserved [roadmap notes](pdf-derived-roadmap-notes.md) for likely dependencies. Use [technical depth](technical-depth.md) when system design, data structures, architecture, or delivery becomes relevant. The optional [term bank](technical-terms.md) can seed plain-language definitions. Verify changing library/API details with current official documentation or an installed documentation tool such as Context7.

## Absolute beginner route

Begin with what a computer is; hardware and software; operating systems; files, folders, formats, and extensions; basic keyboard, browser, terminal, and editor use as relevant. Then teach internet basics and how programs run. Move to language fundamentals before framework features. A learner who already knows these basics may start at the first unmet prerequisite.

## Sequencing by target

- Frontend: computer and internet foundations if needed → HTML → CSS → programming language fundamentals → TypeScript if chosen → UI framework → testing and delivery.
- Backend: computer and internet foundations if needed → language fundamentals → HTTP/API concepts → data modeling and SQL when relevant → persistence and security → framework-specific implementation → testing and operations.
- Fullstack: combine those paths and introduce frontend-to-backend integration only after both sides and HTTP are understood.
- Teach architecture, UML, DSA, queues, Docker, Kubernetes, or system design when they serve an outcome or project. Introduce each inside a concrete problem and at a depth appropriate to the course. Do not force an advanced module into a short beginner course.

Treat TypeScript, Bun, Drizzle, modular monoliths, and versioned API routes as **stack-specific choices**, not universal rules. When the teacher names a stack, follow it. When none is specified, choose a coherent beginner-friendly path and record the choice in the course map before using it in examples. Source code examples and package commands from current language and framework documentation.

Use roadmap.sh for breadth and likely prerequisites when it fits the selected technical topic. Use official framework/language docs for syntax and behavior. A beginner tutorial may supplement these sources, but never replace an authoritative API reference. Include only verified and relevant links in the lesson.
