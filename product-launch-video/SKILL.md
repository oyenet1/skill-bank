# Product Launch in Remotion

Accept product screenshots as the main input; also use any supplied product brief, site, repository, brand assets, screen recording, or teacher/founder footage. Read available product information and inspect every selected screenshot before writing claims or motion. A screenshot-only request is workable. Ask only for a missing decision that changes the deliverable; infer ordinary defaults and label unverified details in the working brief.

Use [the production workflow](references/workflow.md) for source review, story, design, Remotion build, and checks. Produce the requested video, not an unrelated course or full marketing campaign. For a course product, the existing course map, sample lesson, and learner projects may supply evidence. For any other product, use its actual source material.

For video production, read any mandatory installed video entrypoint skill first, then `remotion-best-practices` and its relevant creation, markup, asset, caption, audio, and render references. The user's explicit Remotion choice controls the deliverable. Check current Remotion documentation for code and CLI usage. Create editable source and render an MP4 when the environment permits; report a specific render blocker if it does not.

Write `style.md` before scenes, with colors, fonts, tone, canvas, safe areas, screenshots, presenter placement, and an effects bible. Use real screenshots as product proof. Animate crops, zooms, callouts, and transitions to direct attention; keep labels and data legible. Do not invent a UI state, click result, performance figure, testimonial, price, or feature that the sources do not support. With only static screenshots, describe the result as a screenshot-based product demo rather than live captured interaction.

Narration, TTS, captions, extra image generation, and a CapCut editing package are separate choices. Use supplied audio or footage when given; synthesize speech only on request. Keep the chosen script, storyboard beat IDs, asset manifest, style, Remotion source, and rendered output together so later edits can be made selectively.
