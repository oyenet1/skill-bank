# Feature Reveal

## When to use
One screen, one feature, one proof. A single screenshot is enough if the screen
is legible.

## Beat structure
| Beat | Time | On screen | Motion | SFX |
|---|---|---|---|---|
| 1 | 0:00–0:05 | The problem, one line | `typewriter` | `typing` |
| 2 | 0:05–0:14 | The real screen — full, readable | `fade-in` or `zoom` to the region | `shutter` |
| 3 | 0:14–0:24 | The one action that matters | `zoom` + `pointer-cursor` + `focus-ring` | `click` |
| 4 | 0:24–0:30 | Ending per §4 | settle | `success` |

## Copy skeleton
`{Problem line.}` / `{What you are looking at.}` / `{The one action.}` / `{CTA.}`

## Objects used
`browser-chrome` `zoom` `pointer-cursor` `focus-ring` `callout-box`

## Variants
- With only static screenshots, describe the result as a **screenshot-based
  demo**. Do not imply a click produced a later state you do not have.
